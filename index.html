匹配规则

        
同一个 font-family 下可以写多条 @font-face。浏览器为每个字符从最后一条往前找，选第一条 unicode-range 包含它、且字体里真有这个字形的规则。所以基础字体（汉字）写在最前，不限范围，负责兜底；半角西文、半角数字等类别写在后面接管各自的范围；例外字符写在最后，优先级最高。

        
大小：size-adjust

        
size-adjust 按百分比缩放一个字体的字形和度量。Chrome/Edge 92+、Firefox 92+、Safari 17+ 支持。它也会放大这个字体的上伸、下伸度量，line-height: normal 时行距可能不均匀，建议写固定的 line-height。

        
「基础设定」里的大小和基线，以及「各字重」里的大小，都可直接输入数值，或用输入框右侧的上下箭头每次增减 0.5。键盘按住 Shift 再按 ↑↓ 时，每次增减 5。清空输入框可恢复继承值。箭头在悬停或聚焦时出现，触屏上常显；显示与隐藏不会改变数字的对齐位置。

        
基线偏移需要 JS

        
@font-face 没有基线描述符。同一行里所有字形都对齐在字母基线上，CSS 无法按字体单独移动。工具里的「基线」会在导出时附带一段脚本，把对应字符包进 <span> 用相对定位移动，不影响行高。想要纯 CSS，就把所有基线保持为 0。

        
自动调整

        
「基础设定」右上角的「自动调整」会按类别匹配独立指定的字体，汉字基础字体保持不变。跟随项继承来源类别的结果，已有的大小、基线覆盖保留。所有需要匹配的字体与参照相同时，提示无需调整，不改现有设置。结果可微调，整次操作可一次撤销。操作提示从屏幕底部滑入，停留后淡出；系统开启「减少动态效果」时直接显示。

        
参照。西文以汉字字体自带的西文为参照，兼顾大写字母和小写 x 的高度，缺少字母时按汉字字面估算；独立数字对照本次调整后的西文数字。假名、全角标点、符号、注音及独立的中西共用标点，对照汉字字体中的同类字符。假名、数字、注音比较对应字符的高度；全角标点、符号与共用标点按对应字符的字身宽度匹配大小，再匹配字形的位置，保留标点的小字面与地区位置。不是把所有字符都放大到汉字高度。

        
例外字符。仅自动匹配原属同一类别、最多 64 个字符的独立例外组，以原类别当前字体中的相同字符为参照。混合类别、未归类字符、范围过大或缺少可靠对应字形时，保留原设置并提示。任一待测字重缺少参照时，保留该类别的全部设置，避免基础设定的改动间接影响未能测量的字重。

        
字重与基线。分档模式在最终大小下比较同类字符的笔画粗细，选择更接近的可用字重，并避免同一字体的粗体比正文更细。西文使用 H、h 的主干，其他类别使用多个对应字符的横纵截面估算；它们都只是视觉匹配的起点。支持 Google Fonts 和带字重轴的本机／上传字体；连续模式、单一字重或量不到可靠笔画时保留粗细。按选中的导出字重测量，并始终测量 400：400 写入基础设定，其他档的大小与基础相差至少 0.5 个百分点时单独保存。基线只保存基础值，小于 2% em 的偏移设为 0；网页偏移需要 JS，字体文件直接写入位置。

        
局部重置与限制。「各字重」类别标题旁的重置按钮恢复该类别的基础大小 100%、基线 0 和最接近常规 400 的可用字重，并清除逐档大小、粗细与独立字体覆盖。保留基础字体选择、其他可变轴、其他类别、共享字体名映射、导出勾选及预览字重，可撤销。自动调整不会创造缺失字重，也不会改变导出勾选。字形风格、衬线反差及设计比例仍需在正文中判断，必要时手动微调或更换字体。

        
本机字体：local()

        
local() 按字体的完整名或 PostScript 名匹配，而不是字族名。例如写 Hiragino Sans GB W3 或 HiraginoSansGB-W3，而不是 Hiragino Sans GB。字体卡片上的绿点表示当前浏览器找到了它。Safari 只允许网页使用系统预装字体，自己安装的字体在 Safari 里不生效。访客电脑上没有这个字体时，会回退到前面一条规则。

        
Google Fonts

        
中日韩字体在 Google Fonts 上被切成上百个分片，每片有自己的 unicode-range。导出时工具会把分片范围和类别范围求交集，只保留需要的分片，所以西文类别通常只剩一两条。url 指向 fonts.gstatic.com，正式项目建议下载后自托管。

        
导出多个字重

        
字体名下用「连续字重」「分档字重」说明可用的粗细：连续字重可在范围内输入任意值，例如「连续字重 200–900」；分档字重只有固定档位，例如「分档字重 400、700」，档位较多时显示最轻到最重的范围，悬停可查看完整档位。这些标注说明字体本身的能力；导出模式在「各字重」里另选。范围无法准确读取时不推测，已知存在可变轴但字重范围不明时标为「字重范围未知」。跟随其他类别的字体信息看来源行。

        
在「各字重」里勾选要导出的字重（导出对话框里也能选），每个字重各生成一组规则。点击任一行的空白处即可预览该字重，不会改变导出勾选。工具里设定的字体对应 400；其他字重里，Google Fonts 的字体按同样的差值换算（例如 500 的字体在 700 时取 800），没有这个字重就取最接近的；本机字体会按名称推测粗体（例如 W3 → W6、Regular → Bold），并在这台电脑上检测。各字体的粗细分布并不一致：「各字重」一览表里可以按字重单独调整各类别的大小和粗细。可变字体的粗细可直接输入任意数值，右侧箭头或键盘 ↑↓ 每次增减 10，Shift + ↑↓ 每次增减 100；静态 Google Fonts 字体按 100 档调整，缺档时跳到下一个可用字重。本机字体名、字体文件，或者只给这个字重换的字体，点那一格，或者用这一行末尾的「⋯」菜单里的「换字体…」，在「选择字体」里指定。Google Fonts 的静态字体只列出它实际有的字重；灰色是推算的值，蓝色是单独设定的，选回灰色那一档就取消单独设定。

        
各字重的规则没法合并。CSS 变量（var()）在 @font-face 里无效，浏览器会直接丢掉这条描述。同一个 font-family 里，如果有的规则写 font-weight: 700、有的写 400 700，实测 Chrome 会把它们分成两组，只用其中一组，合成就失效了。

        
真正占体积的是汉字字体在 Google Fonts 上的上百个分片。「基础字体：引用 Google Fonts」会用 @import 直接引用 Google 的 CSS，把这个字体排在 font-family 的第二位，自己只写需要覆盖它的类别，导出的 CSS 通常只有几 KB。服务器一般会用 gzip 压缩 CSS，导出区显示的 gzip 体积更接近实际传输量。字体文件只按页面用到的字符下载，与 CSS 长度无关。

        
分档模式下，在字体选择器里提交修改或改变跟随关系时，会检查各行实际使用的字体和粗细，自动取消明确超出已知字重范围的导出勾选。网页和字体文件的选择分别检查；有效的单独映射、范围内的静态缺档，以及范围未知的字体都会保留。取消勾选不删除该行的调整，可重新勾选；换字体和自动取消可一起撤销。若某组已选字重全部越界，则保留原勾选并提示手动确认。换成范围更大的字体不会自动勾回字重；连续模式的选择与范围不自动调整。

        
斜体

        
没有斜体规则时，<em> 和 <i> 里的字全部由浏览器模拟倾斜：西文明明有斜体也不用，汉字也会歪掉。所以默认导出斜体，每组规则另有一份 font-style: italic：西文用真正的斜体（Google Fonts 的 Italic、上传的斜体文件、本机的「… Italic」，或者可变字体的 slnt / ital 轴）；没有斜体的类别用正体文件、也声明成 italic，浏览器就不会去模拟。基础字体用 @import 引用时，Google 那边只有正体，所以使用规则里加了 font-synthesis-style: none，让它同样保持正体。

        
可变轴

        
「选择字体…」里可以调可变字体的其他轴，例如宽度、笔画粗细（GRAD）、光学尺寸。Google Fonts 只保留请求里写了的轴，其余固定在默认值、从文件里去掉，所以调过的轴会加进请求，文件大约变成两倍。固定的值写在 @font-face 的 font-variation-settings 里，Safari 不认这一行，会按默认值显示。光学尺寸选「跟随字号」时，浏览器按实际字号设定 opsz；实测 Chrome 用的是 size-adjust 放大之后的字号，正好对应西文实际显示的大小。

        
「字体」页签「字体特性」里的「数字样式」「斜线零」对应 font-variant-numeric，写在使用规则里（Chrome 52+、Firefox 34+、Safari 9.1+），页面上还可以按元素改，比如只让表格用等宽数字。效果取决于显示数字的那个字体有没有这些 OpenType 特性：工具会检测它默认是哪种数字，选了它没有的样式时会提示。Google Fonts 的网页字体删掉了大部分特性，没有旧式数字和斜线零。

        
行高度量：合成字体的行高（line-height: normal）和基线在行里的位置，浏览器取自负责空格的那条规则，也就是半角西文的字体，而且是 size-adjust 放大之后的。导出时默认给基础字体以外的规则写上汉字字体的 ascent-override、descent-override、line-gap-override；size-adjust 会把它们再放大一次，所以写的是除过之后的值。这样排出来和纯汉字字体一样。Chrome 87+、Firefox 89+ 支持，Safari 会忽略。

        
繁体中文：台湾和香港

        
「适用语言」的繁体中文分成台湾和香港两种。导出时用 :is(:lang(…)) 把常见写法都包进去：台湾版匹配 zh-Hant、zh-TW，香港版匹配 zh-HK、zh-Hant-HK 和澳门的写法。原因是 :lang(zh-Hant) 匹配不到 lang="zh-TW"：浏览器不会从地区推出文字。简体中文同样会加上 zh-CN、zh-SG。

        
两地的写法和大陆不同：标点在字身正中（大陆、日本靠左下），字形也按各自的标准。工具会量全角标点的位置，并按字族名判断字形的地区：和校样的语言不一致时在类别表里提示，和适用语言不一致时在导出区提示。思源、Noto CJK 这类一个文件含多个地区字形的字体会按 lang 切换，所以测量时也带上语言。

        
类别表里有一行「注音符号」，也负责声调号 ˊ ˇ ˋ ˙：它们原本属于西文的码位，不归过来就会用西文字体显示。法语等的重音字母（é、à）是另外的码位，不受影响；需要的话可以在齿轮里把声调号改回半角西文。

        
App 代码（实验性）

        
iOS、Android 和 Flutter 没有复合字体。导出里的「App 代码」生成一段 Swift、Kotlin 或 Dart：按字符类别把文字切成片段，每段分别设字体、大小和基线偏移，字符范围和网页导出完全相同。代码里的字体名称（PostScript 名、文件名、family）是推测的，要对照 App 里实际打包的字体改；混用不同大小的字会让行高变化，没有网页那样的行高修正；Flutter 不能单独移动基线。三种代码都编译过（Kotlin 对着 Android API，Flutter 通过 analyze 和 test），切分结果也核对过，但没有在真机上看过排版效果，发现问题欢迎在 GitHub 提交 PR 或 Issue。字体授权允许的话，把生成的字体文件打包进 App 效果最完整。

        
字体文件

        
「字体文件」页签把合成字体做成真正的字体（TTF、WOFF2、OTF，可任选），给 Figma、Keynote、Word 这类不支持合成字体的软件用。做法和导出的 CSS 一一对应：每条规则的字体只取它负责的字，按大小缩放、按基线上下平移，再合并成一个字体；行高度量用汉字基础字体的。生成在浏览器里进行（Pyodide + fontTools），字体不会上传到任何服务器。

        
源字体：Google Fonts 的字体从 google/fonts 仓库下载完整文件，网页接口给的切片去掉了大部分 OpenType 特性；上传的字体直接使用；本机安装的字体通过浏览器的本机字体接口读取（Chrome、Edge，需要授权）。CFF 轮廓的 OTF 会转换成 TrueType 曲线（误差不超过 1/1000 em），字体集合（TTC）只取用到的那一款。只有 OFL、Apache 等允许修改的许可可以直接合并，许可不明的字体（包括系统自带和商用的字体）要先确认有权修改，生成的文件只给自己用。字体微调（hinting）会去掉，只影响 Windows 上的小字号。浏览器会在中西文之间自动加 1/8 em 的间距，其他软件不会。

        
格式：合并只能在 TrueType 曲线上做，所以 OTF 是最后从合并结果转换成 CFF 曲线得到的。浏览器里能跑的字体库（fontTools）不能合并中日文 OTF 常用的 CID 结构 CFF，也不能把 TrueType 和 CFF 曲线放进同一个字体；能直接合并 CFF、生成 CID 结构 OTF 的 Adobe AFDKO 是 C 程序，不能在浏览器里运行。所以源字体是 CFF 时，会经过「三次曲线 → 二次曲线 → 三次曲线」的转换（误差不超过 1/1000 em，印刷上看不出），生成的 OTF 也不是 CID 结构。现在的软件都能正常使用，个别要求 CID 字体的老印刷流程可能不接受。

        
为什么不用 font-size-adjust

        
font-size-adjust（Chrome 127、Firefox 92、Safari 17 支持双值语法）也能统一字号，但它对元素里的每个字体都生效：把西文调到目标大写高的同时，汉字字体也会按它自带的西文度量被缩放。它也不能按字符类别分配字体，解决不了引号归属。更关键的是，MDN 指出它和 @font-face 的 size-adjust 同时出现时，size-adjust 不再起作用。所以使用复合字体的元素上不要再写 font-size-adjust。校样的「对照其他做法」里可以切换到这个做法比较效果。

比對規則

        
同一個 font-family 下可以寫多條 @font-face。瀏覽器為每個字元從最後一條往前找，選第一條 unicode-range 包含它、且字型裡真有這個字形的規則。所以基礎字型（漢字）寫在最前，不限範圍，負責其餘所有字元；半形西文、半形數字等類別寫在後面接管各自的範圍；例外字元寫在最後，優先順序最高。

        
大小：size-adjust

        
size-adjust 按百分比縮放一個字型的字形和度量。Chrome/Edge 92+、Firefox 92+、Safari 17+ 支援。它也會放大這個字型的上伸、下伸度量，line-height: normal 時行距可能不均勻，建議寫固定的 line-height。

        
「基礎設定」裡的大小與基線，以及「各字重」裡的大小，都可直接輸入數值，或使用輸入框右側的上下箭頭每次增減 0.5。鍵盤按住 Shift 再按 ↑↓ 時，每次增減 5。清空輸入框可恢復繼承值。箭頭在滑鼠停留或聚焦時出現，觸控螢幕上持續顯示；顯示與隱藏不會改變數字的對齊位置。

        
基線偏移需要 JS

        
@font-face 沒有基線描述子。同一行裡所有字形都對齊在字母基線上，CSS 無法按字型單獨移動。工具裡的「基線」會在匯出時附帶一段 JS，把對應字元包進 <span> 用相對定位移動，不影響行高。想要純 CSS，就把所有基線保持為 0。

        
自動調整

        
「基礎設定」右上角的「自動調整」會依類別調整獨立指定的字型，漢字基礎字型維持不變。跟隨項目繼承來源類別的結果，已個別設定的大小與基線保留。所有需要調整的字型與參照相同時，提示無須調整，不改現有設定。結果可微調，整次操作可一次復原。操作提示從螢幕底部滑入，停留後淡出；系統開啟「減少動態效果」時直接顯示。

        
參照。西文以漢字字型內建的西文為參照，兼顧大寫字母與小寫 x 的高度，缺少字母時按漢字字面估算；獨立數字對照本次調整後的西文數字。假名、全形標點、符號、注音及獨立的中西共用標點，對照漢字字型中的同類字元。假名、數字、注音比較對應字元的高度；全形標點、符號與共用標點依對應字元的字身寬度調整大小，再對齊字形位置，保留標點的小字面與地區位置，不將所有字元放大至漢字高度。

        
例外字元。僅自動調整原屬同一類別、最多 64 個字元的獨立例外群組，以原類別目前字型中的相同字元為參照。混合類別、未分類字元、範圍過大或缺少可靠對應字形時，保留原設定並提示。任一待測字重缺少參照時，保留該類別的全部設定，避免基礎設定的變動間接影響無法測量的字重。

        
字重與基線。分段模式在調整後的大小比較同類字元的筆畫粗細，選擇較接近的可用字重，並避免同一字型的粗體比正文更細。西文使用 H、h 的主幹，其他類別使用多個對應字元的橫縱截面估算，僅作為視覺調整的起點。支援 Google Fonts 與有字重軸的本機／上傳字型；連續模式、單一字重或無法測量可靠筆畫時保留粗細。依勾選的匯出字重測量，並一律測量 400：400 寫入基礎設定，其他字重的大小與基礎相差至少 0.5 個百分點時個別儲存。基線只儲存基礎值，小於 2% em 的偏移設為 0；網頁偏移需要 JS，字型檔案直接寫入位置。

        
個別重設與限制。「各字重」類別標題旁的重設按鈕會恢復該類別的基礎大小 100%、基線 0 與最接近標準 400 的可用字重，並清除各字重的大小、粗細與獨立字型設定。保留基礎字型選擇、其他可變軸、其他類別、共用字型名稱對應、匯出勾選與預覽字重，並可復原。自動調整無法建立缺少的字重，也不會改變匯出勾選。字形風格、襯線對比與設計比例仍需在正文中判斷，必要時手動微調或更換字型。

        
本機字型：local()

        
local() 按字型的完整名或 PostScript 名比對，而不是字族名。例如寫 Hiragino Sans GB W3 或 HiraginoSansGB-W3，而不是 Hiragino Sans GB。字型卡片上的綠點表示目前瀏覽器找到了它。Safari 只允許網頁使用系統預裝字型，自己安裝的字型在 Safari 裡不生效。訪客電腦上沒有這個字型時，會改用前面一條規則。

        
Google Fonts

        
中日韓字型在 Google Fonts 上被切成上百個分片，每片有自己的 unicode-range。匯出時工具會把分片範圍和類別範圍求交集，只保留需要的分片，所以西文類別通常只剩一兩條。url 指向 fonts.gstatic.com，正式專案建議下載後自行託管。

        
匯出多個字重

        
字型名下使用「連續字重」「分段字重」說明可用的粗細：連續字重可在範圍內輸入任意值，例如「連續字重 200–900」；分段字重只有固定檔位，例如「分段字重 400、700」，檔位較多時顯示最細到最粗的範圍，滑鼠移到標示上可查看完整檔位。這些標示說明字型本身的能力；匯出模式在「各字重」裡另外選擇。無法確切讀取範圍時不推測，已知具有可變軸但字重範圍不明時標為「字重範圍未知」。跟隨其他類別時，請查看來源列的字型資訊。

        
在「各字重」裡勾選要匯出的字重（匯出對話框裡也能選），每個字重各生成一組規則。點選任一列的空白處即可預覽該字重，不會改變匯出勾選。工具裡設定的字型對應 400；其他字重裡，Google Fonts 的字型按同樣的差值換算（例如 500 的字型在 700 時取 800），沒有這個字重就取最接近的；本機字型會按名稱推測粗體（例如 W3 → W6、Regular → Bold），並在這台電腦上檢測。各字型的粗細分布並不一致：「各字重」表格裡可以按字重個別調整各類別的大小與粗細。可變字型的粗細可直接輸入任意數值，右側箭頭或鍵盤 ↑↓ 每次增減 10，Shift + ↑↓ 每次增減 100；靜態 Google Fonts 字型按 100 檔調整，缺檔時跳到下一個可用字重。本機字型名、字型檔案，或者只給這個字重換的字型，點那一格，或者用這一列末尾的「⋯」選單裡的「換字型…」，在「選擇字型」裡指定。Google Fonts 的靜態字型只列出它實際有的字重；灰色是推算的值，藍色是單獨設定的，選回灰色那一檔就取消單獨設定。

        
各字重的規則沒法合併。CSS 變數（var()）在 @font-face 裡無效，瀏覽器會直接丟掉這條描述。同一個 font-family 裡，如果有的規則寫 font-weight: 700、有的寫 400 700，實測 Chrome 會把它們分成兩組，只用其中一組，合成就失效了。

        
真正佔體積的是漢字字型在 Google Fonts 上的上百個分片。「基礎字型：引用 Google Fonts」會用 @import 直接引用 Google 的 CSS，把這個字型排在 font-family 的第二位，自己只寫需要覆蓋它的類別，匯出的 CSS 通常只有幾 KB。伺服器一般會用 gzip 壓縮 CSS，匯出區顯示的 gzip 體積更接近實際傳輸量。字型檔案只按頁面用到的字元下載，與 CSS 長度無關。

        
分檔模式下，在字型選擇器裡套用修改或改變跟隨關係時，會檢查各列實際使用的字型與粗細，自動取消明確超出已知字重範圍的匯出勾選。網頁與字型檔案的選擇分別檢查；有效的個別對應、範圍內的靜態字重缺檔，以及範圍未知的字型都會保留。取消勾選不會刪除該列的調整，可重新勾選；更換字型與自動取消可一起復原。若某組已選字重全部超出範圍，則保留原勾選並提示手動確認。換成範圍更大的字型不會自動勾回字重；連續模式的選擇與範圍不自動調整。

        
斜體

        
沒有斜體規則時，<em> 和 <i> 裡的字全部由瀏覽器模擬傾斜：西文明明有斜體也不用，漢字也會歪掉。所以預設匯出斜體，每組規則另有一份 font-style: italic：西文用真正的斜體（Google Fonts 的 Italic、上傳的斜體檔案、本機的「… Italic」，或者可變字型的 slnt / ital 軸）；沒有斜體的類別用一般（非斜體）的檔案、也宣告成 italic，瀏覽器就不會去模擬。基礎字型用 @import 引用時，Google 那邊只有一般字形，所以使用規則裡加了 font-synthesis-style: none，讓它同樣保持直立。

        
可變軸

        
「選擇字型…」裡可以調可變字型的其他軸，例如寬度、筆畫粗細（GRAD）、光學尺寸。Google Fonts 只保留請求裡寫了的軸，其餘固定在預設值、從檔案裡去掉，所以調過的軸會加進請求，檔案大約變成兩倍。固定的值寫在 @font-face 的 font-variation-settings 裡，Safari 不認這一行，會按預設值顯示。光學尺寸選「跟隨字號」時，瀏覽器按實際字號設定 opsz；實測 Chrome 用的是 size-adjust 放大之後的字號，正好對應西文實際顯示的大小。

        
「字型」頁籤「字型特性」裡的「數字樣式」「斜線零」對應 font-variant-numeric，寫在使用規則裡（Chrome 52+、Firefox 34+、Safari 9.1+），頁面上還可以按元素改，比如只讓表格用等寬數字。效果取決於顯示數字的那個字型有沒有這些 OpenType 特性：工具會檢測它預設是哪種數字，選了它沒有的樣式時會提示。Google Fonts 的網頁字型刪掉了大部分特性，沒有舊式數字和斜線零。

        
行高度量：複合字型的行高（line-height: normal）和基線在行裡的位置，瀏覽器取自負責空格的那條規則，也就是半形西文的字型，而且是 size-adjust 放大之後的。匯出時預設給基礎字型以外的規則寫上漢字字型的 ascent-override、descent-override、line-gap-override；size-adjust 會把它們再放大一次，所以寫的是除過之後的值。這樣排出來和純漢字字型一樣。Chrome 87+、Firefox 89+ 支援，Safari 會忽略。

        
繁體中文：台灣和香港

        
「適用語言」的繁體中文分成台灣和香港兩種。匯出時用 :is(:lang(…)) 把常見寫法都包進去：台灣版比對 zh-Hant、zh-TW，香港版比對 zh-HK、zh-Hant-HK 和澳門的寫法。原因是 :lang(zh-Hant) 比對不到 lang="zh-TW"：瀏覽器不會從地區推出文字。簡體中文同樣會加上 zh-CN、zh-SG。

        
兩地的寫法和中國大陸不同：標點居中（大陸、日本靠左下），字形也依各自的標準。工具會量全形標點的位置，並依字族名判斷字形的地區：和校樣的語言不一致時在類別表裡提示，和適用語言不一致時在匯出區提示。思源、Noto CJK 這類一個檔案含多個地區字形的字型會依 lang 切換，所以測量時也帶上語言。

        
類別表裡有一行「注音符號」，也負責聲調號 ˊ ˇ ˋ ˙：它們原本屬於西文的碼位，不歸過來就會用西文字型顯示。法語等的重音字母（é、à）是另外的碼位，不受影響；需要的話可以在齒輪裡把聲調號改回半形西文。

        
App 程式碼（實驗性）

        
iOS、Android 和 Flutter 沒有複合字型。匯出裡的「App 程式碼」產生一段 Swift、Kotlin 或 Dart：按字元類別把文字切成片段，每段分別設字型、大小和基線偏移，字元範圍和網頁匯出完全相同。程式碼裡的字型名稱（PostScript 名、檔名、family）是推測的，要對照 App 裡實際打包的字型改；混用不同大小的字會讓行高變化，沒有網頁那樣的行高修正；Flutter 不能單獨移動基線。三種程式碼都編譯過（Kotlin 對著 Android API，Flutter 通過 analyze 和 test），切分結果也核對過，但沒有在實機上看過排版效果，發現問題歡迎在 GitHub 提交 PR 或 Issue。字型授權允許的話，把產生的字型檔案打包進 App 效果最完整。

        
字型檔案

        
「字型檔案」頁籤把複合字型做成真正的字型（TTF、WOFF2、OTF，可任選），給 Figma、Keynote、Word 這類不支援複合字型的軟體用。做法和匯出的 CSS 一一對應：每條規則的字型只取它負責的字，按大小縮放、按基線上下平移，再合併成一個字型；行高度量用漢字基礎字型的。產生在瀏覽器裡進行（Pyodide + fontTools），字型不會上傳到任何伺服器。

        
來源字型：Google Fonts 的字型從 google/fonts 倉庫下載完整檔案，網頁介面給的切片去掉了大部分 OpenType 特性；上傳的字型直接使用；本機安裝的字型透過瀏覽器的本機字型介面讀取（Chrome、Edge，需要授權）。CFF 輪廓的 OTF 會轉換成 TrueType 曲線（誤差不超過 1/1000 em），字型集合（TTC）只取用到的那一款。只有 OFL、Apache 等允許修改的授權可以直接合併，授權不明的字型（包括系統內建和商用的字型）要先確認有權修改，產生的檔案只給自己用。字型微調（hinting）會去掉，只影響 Windows 上的小字號。瀏覽器會在中西文之間自動加 1/8 em 的間距，其他軟體不會。

        
格式：合併只能在 TrueType 曲線上做，所以 OTF 是最後從合併結果轉換成 CFF 曲線得到的。瀏覽器裡能跑的字型函式庫（fontTools）不能合併中日文 OTF 常用的 CID 結構 CFF，也不能把 TrueType 和 CFF 曲線放進同一個字型；能直接合併 CFF、產生 CID 結構 OTF 的 Adobe AFDKO 是 C 程式，不能在瀏覽器裡執行。所以來源字型是 CFF 時，會經過「三次曲線 → 二次曲線 → 三次曲線」的轉換（誤差不超過 1/1000 em，印刷上看不出），產生的 OTF 也不是 CID 結構。現在的軟體都能正常使用，個別要求 CID 字型的舊印刷流程可能不接受。

        
為什麼不用 font-size-adjust

        
font-size-adjust（Chrome 127、Firefox 92、Safari 17 支援雙值語法）也能統一字號，但它對元素裡的每個字型都生效：把西文調到目標大寫高的同時，漢字字型也會按它自帶的西文度量被縮放。它也不能按字元類別分配字型，解決不了引號歸屬。更關鍵的是，MDN 指出它和 @font-face 的 size-adjust 同時出現時，size-adjust 不再起作用。所以使用複合字型的元素上不要再寫 font-size-adjust。校樣的「對照其他做法」裡可以切換到這個做法比較效果。

照合の規則

        
同じ font-family 名で複数の @font-face を書けます。ブラウザは文字ごとに最後の規則からさかのぼり、unicode-range にその文字を含み、実際にグリフを持つ最初の規則を使います。そのため、ベースフォント（漢字）を最初に範囲指定なしで書いてすべてを受け持たせ、半角欧文や半角数字などのクラスを後に書いて担当範囲を引き受けさせます。例外文字は最後に書くので、優先度が最も高くなります。

        
サイズ：size-adjust

        
size-adjust はフォントのグリフとメトリクスをパーセントで拡大縮小します。Chrome/Edge 92+、Firefox 92+、Safari 17+ が対応しています。アセンダーとディセンダーも拡大されるため、line-height: normal では行送りが不揃いになることがあります。line-height は固定値で指定するのがおすすめです。

        
「基本設定」のサイズとベースライン、および「ウェイト別」のサイズは、数値を直接入力するか、入力欄右側の上下の矢印で 0.5 ずつ調整できます。Shift を押しながらキーボードの ↑↓ を押すと 5 ずつ変わります。入力を消すと継承値に戻ります。矢印はホバー時やフォーカス時に表示され、タッチ画面では常に表示されます。表示が切り替わっても数値の位置は変わりません。

        
ベースラインシフトには JS が必要

        
@font-face にはベースラインの記述子がありません。同じ行のグリフはすべて欧文ベースラインにそろうため、CSS だけではフォントごとに上下させられません。ツールの「ベースライン」を使うと、書き出し時に小さなスクリプトが付きます。対象の文字を <span> で包んで相対位置で動かすので、行の高さは変わりません。CSS だけで済ませたい場合は、すべてのベースラインを 0 にしてください。

        
自動調整

        
「基本設定」の右上にある「自動調整」は、独立して指定したフォントを文字クラスごとに調整します。漢字のベースフォントは変更しません。追従するクラスは参照先の結果を継承し、個別に指定したサイズとベースラインは維持します。対象フォントがすべて参照フォントと同じなら、調整不要と通知し、設定は変更しません。結果は微調整でき、操作全体を一度で取り消せます。通知は画面下からスライドして現れ、しばらく表示してから消えます。視差効果の低減が有効な場合は動かさず表示します。

        
参照。欧文は漢字フォント内蔵の欧文を基準に、大文字と小文字 x の高さを考慮します。参照文字がなければ漢字の字面から推定します。独立した数字は今回調整した欧文の数字に合わせます。かな、全角約物、記号、注音、独立した和欧共通約物は、漢字フォント内の同じ文字を参照します。かな・数字・注音は対応する文字の高さ、全角約物・記号・共通約物は字幅でサイズを合わせてから位置を合わせます。小さい約物の字面や地域ごとの位置を保ち、すべてを漢字の高さには拡大しません。

        
例外文字。元の文字クラスが一つで、64 文字以内の独立した例外グループだけを自動調整し、元のクラスの現在のフォントにある同じ文字を参照します。複数クラス、未分類文字、広すぎる範囲、信頼できる参照がない場合は、設定を維持して通知します。測定するウェイトの一つでも参照が不足する場合、そのクラス全体を維持し、基本設定の変更が未測定のウェイトに影響するのを防ぎます。

        
ウェイトとベースライン。段階モードでは調整後のサイズで対応する文字の線の太さを比較し、同じフォントの太字が本文より細くならないよう、より近いウェイトを選びます。欧文は H・h の主画、ほかは複数の文字の縦横断面から推定し、視覚調整の出発点とします。Google Fonts とウェイト軸を持つローカル・アップロードフォントに対応します。連続モード、単一ウェイト、信頼できる線幅を測れない場合は太さを維持します。選択した書き出しウェイトと必ず 400 を測り、400 は基本設定、ほかは基本と 0.5 ポイント以上違うサイズだけ個別に保存します。ベースラインは基本値のみを保存し、2% em 未満は 0 にします。Web のシフトには JS が必要で、フォントファイルには位置を直接反映します。

        
個別リセットと制限。「ウェイト別」のクラス見出し横のボタンは、そのクラスの基本サイズを 100%、ベースラインを 0、調整可能なウェイトを通常の 400 に最も近い値に戻し、ウェイト別の個別設定を消去します。ベースフォントの選択、ほかの可変軸と文字クラス、共有のフォント名対応、書き出し選択、プレビューのウェイトは維持し、取り消しもできます。自動調整は不足するウェイトを作らず、書き出し選択も変えません。字形、セリフのコントラスト、設計上の比率は本文で確認し、必要に応じて微調整するかフォントを変えてください。

        
ローカルフォント：local()

        
local() はファミリー名ではなく、フルネームか PostScript 名で照合します。たとえば Hiragino Sans GB ではなく、Hiragino Sans GB W3 または HiraginoSansGB-W3 と書きます。フォントカードの緑の点は、現在のブラウザがそのフォントを見つけたことを示します。Safari はシステムにプリインストールされたフォントしか Web で使わせないため、自分でインストールしたフォントは Safari では効きません。閲覧者の環境にフォントがない場合は、ひとつ前の規則にフォールバックします。

        
Google Fonts

        
CJK フォントは Google Fonts で 100 以上のサブセットに分割され、それぞれに unicode-range があります。書き出し時にサブセットの範囲とクラスの範囲の共通部分を取り、必要なサブセットだけを残すので、欧文クラスは通常 1〜2 件になります。url は fonts.gstatic.com を指しています。本番ではダウンロードしてセルフホストすることをおすすめします。

        
複数のウェイトを書き出す

        
フォント名の下に「連続ウェイト」「段階ウェイト」と表示します。連続ウェイトは「連続ウェイト 200–900」のように、その範囲で任意の太さを入力できます。段階ウェイトは「段階ウェイト 400、700」のように決まった太さを持ち、数が多い場合は最小〜最大の範囲を表示します。マウスを重ねると全ウェイトを確認できます。これはフォント自体の情報で、書き出しモードは「ウェイト別」で選びます。正確な範囲は推測せず、可変軸があってもウェイト範囲が不明なら「ウェイト範囲不明」と表示します。ほかのクラスに追従する場合は、追従元の行の情報を参照してください。

        
「ウェイト別」で書き出すウェイトにチェックを入れると（書き出しダイアログでも選べます）、ウェイトごとに規則を 1 組ずつ生成します。各行の空白部分をクリックすると、そのウェイトをプレビューできます。書き出しのチェックは変わりません。ツールで設定したフォントは 400 に対応します。ほかのウェイトでは、Google Fonts のフォントは同じ差分で換算し（500 のフォントなら 700 のとき 800）、そのウェイトがなければ最も近いものを使います。ローカルフォントは名前から太字の名前を推測し（W3 → W6、Regular → Bold など）、このデバイスで確認します。フォントごとにウェイトの分布は異なるので、「ウェイト別」の表でウェイトごとに各クラスのサイズと太さを個別に調整できます。可変フォントの太さは任意の数値を直接入力でき、右側の矢印やキーボードの ↑↓ で 10 ずつ、Shift + ↑↓ で 100 ずつ調整できます。静的な Google Fonts は 100 刻みで調整し、存在しないウェイトは飛ばします。ローカルフォント名やファイル、そのウェイトだけ別のフォントにする場合は、そのセルか、行の末尾にある「⋯」メニューの「フォントを変更…」から「フォントを選択」で指定します。Google Fonts の静的フォントは実際にあるウェイトだけを表示します。グレーは自動で決まった値、青は個別に設定した値で、グレーの値を選び直すと個別の設定が解除されます。

        
ウェイトごとの規則はまとめられません。CSS 変数（var()）は @font-face の中では無効で、ブラウザはその記述を捨てます。同じ font-family の中に font-weight: 700 の規則と 400 700 の規則が混ざると、Chrome は実測で別のグループとして扱い、片方しか使わないため、合成が効かなくなります。

        
容量の大半は、Google Fonts で 100 以上に分割された漢字フォントの規則です。「ベースフォント：Google Fonts を参照」では Google の CSS を @import で直接参照し、そのフォントを font-family の 2 番目に置いて、上書きするクラスだけを書き出します。書き出す CSS は通常数 KB です。サーバーは CSS を gzip で圧縮するのが一般的なので、書き出し欄の gzip 後のサイズが実際の転送量に近い値です。フォントファイルはページで使う文字の分だけダウンロードされ、CSS の長さとは関係ありません。

        
段階モードでフォント選択画面の変更を適用するか、追従先を変えると、各行で実際に使うフォントと太さを確認し、既知のウェイト範囲から明らかに外れる書き出しのチェックを外します。Web とフォントファイルの選択は別々に確認します。有効な個別の対応、静的フォントの範囲内の欠番、範囲が不明なフォントは維持します。チェックを外しても行の調整は削除せず、再選択できます。フォントの変更と自動解除はまとめて取り消せます。選択中のウェイトがすべて範囲外なら選択を維持し、手動確認を促します。範囲の広いフォントに変えても自動でチェックは戻しません。連続モードの選択と範囲は自動調整しません。

        
イタリック

        
イタリックの規則がないと、<em> や <i> の中の文字はすべてブラウザが擬似的に傾けます。欧文に本物のイタリックがあっても使われず、漢字まで斜めになります。そのため既定でイタリックを書き出します。各組の規則に font-style: italic の版が加わります。欧文は本物のイタリック（Google Fonts の Italic、読み込んだイタリックのファイル、ローカルの「… Italic」、または可変フォントの slnt / ital 軸）を使い、イタリックのないクラスは正体のファイルを italic として宣言するので、ブラウザは擬似的に傾けません。ベースフォントを @import で参照する場合、Google 側には正体しかないため、使用側の規則に font-synthesis-style: none を加えて正体のままにしています。

        
可変軸

        
「フォントを選択…」で、幅・グレード（GRAD）・オプティカルサイズなど、可変フォントのほかの軸を調整できます。Google Fonts はリクエストに書いた軸だけを残し、残りは既定値に固定してファイルから取り除くため、調整した軸はリクエストに加わり、ファイルはおよそ 2 倍になります。固定した値は @font-face の font-variation-settings に書かれ、Safari はこの行を無視して既定値で表示します。オプティカルサイズを「文字サイズに追従」にすると、ブラウザが実際の文字サイズから opsz を決めます。Chrome は実測で size-adjust で拡大した後のサイズを使うので、欧文が実際に表示される大きさと一致します。

        
「フォント」タブの「フォントの機能」にある「数字のスタイル」「スラッシュ付きゼロ」は font-variant-numeric に対応し、使用側の規則に書かれます（Chrome 52+、Firefox 34+、Safari 9.1+）。ページでは要素ごとに変えることもでき、たとえば表だけ等幅数字にできます。効果は数字を表示するフォントにこれらの OpenType 機能があるかどうかで決まります。ツールはそのフォントの既定の数字を調べ、ない機能を選ぶと知らせます。Google Fonts の Web フォントでは多くの機能が削られていて、オールドスタイル数字とスラッシュ付きゼロはありません。

        
行のメトリクス：合成フォントの行の高さ（line-height: normal）と、行の中のベースラインの位置は、スペースを受け持つ規則、つまり半角欧文のフォント（それも size-adjust で拡大した後のもの）から決まります。書き出しでは既定で、ベース以外の規則に漢字フォントの ascent-override・descent-override・line-gap-override を書きます。size-adjust がもう一度掛かるので、割り戻した値です。これで漢字フォントだけで組んだときと同じになります。Chrome 87+、Firefox 89+ が対応し、Safari は無視します。

        
繁体字中国語：台湾と香港

        
「対象の言語」の繁体字中国語は、台湾と香港の 2 つに分かれています。書き出しでは :is(:lang(…)) でよく使われる書き方をまとめて指定します。台湾版は zh-Hant・zh-TW、香港版は zh-HK・zh-Hant-HK とマカオの書き方に一致します。:lang(zh-Hant) は lang="zh-TW" に一致しないためです（ブラウザは地域から文字体系を推測しません）。簡体字も同様に zh-CN・zh-SG を加えます。

        
台湾と香港では句読点を字面の中央に置き（中国大陸・日本は左下寄り）、字形もそれぞれの規範に従います。ツールは全角約物の位置を測り、ファミリー名から字形の地域を判断します。校正刷りの言語と一致しないときは文字クラスの表で、対象の言語と一致しないときは書き出し欄で知らせます。源ノ角ゴシックや Noto CJK のように 1 つのファイルに複数地域の字形を持つフォントは lang で切り替わるので、測るときも言語を指定しています。

        
文字クラスの表には「注音符号」の行があり、声調記号 ˊ ˇ ˋ ˙ も受け持ちます。もとは欧文の範囲にあり、移さないと欧文フォントで表示されるためです。フランス語などのアクセント付き文字（é・à）は別の符号位置なので影響しません。必要なら歯車から声調記号を半角欧文に戻せます。

        
アプリのコード（試験的）

        
iOS・Android・Flutter には合成フォントがありません。書き出しの「アプリのコード」は Swift・Kotlin・Dart のコードを生成し、文字クラスごとにテキストを区切って、それぞれにフォント・サイズ・ベースラインの調整を設定します。文字の範囲は Web の書き出しとまったく同じです。コード内のフォント名（PostScript 名・ファイル名・family）は推定なので、アプリに同梱したフォントに合わせて直してください。サイズの違う文字が混ざると行の高さが変わり、Web のような行の高さの補正はありません。Flutter ではベースラインを部分的に動かせません。3 種類ともコンパイルし（Kotlin は Android API に対して、Flutter は analyze と test）、区切り方も確認済みですが、実機での組版の見た目は確認していません。問題を見つけたら GitHub で PR や Issue をお寄せください。フォントのライセンスが許せば、生成したフォントファイルをアプリに同梱するのがいちばん確実です。

        
フォントファイル

        
「フォントファイル」タブでは、合成フォントを本物のフォント（TTF・WOFF2・OTF から選べます）にします。Figma、Keynote、Word など合成フォントに対応していないアプリで使うためのものです。書き出す CSS と同じ規則で、各フォントから担当する文字だけを取り出し、サイズとベースラインを調整してから 1 つのフォントにまとめます。行の高さは漢字のベースフォントに合わせます。処理はブラウザの中で行い（Pyodide + fontTools）、フォントがサーバーに送られることはありません。

        
元のフォント：Google Fonts のフォントは google/fonts リポジトリから完全なファイルをダウンロードします。Web 用の配信ではほとんどの OpenType 機能が削られているためです。アップロードしたフォントはそのまま使い、このコンピュータのフォントはブラウザのローカルフォント API で読み取ります（Chrome、Edge。許可が必要です）。CFF アウトラインの OTF は TrueType の曲線に変換し（誤差は 1/1000 em 以下）、フォントコレクション（TTC）からは使われている 1 書体だけを取り出します。合成できるのは OFL や Apache など改変を許可するライセンスのフォントで、ライセンス不明のフォント（OS 付属のフォントや商用フォントを含む）は、改変する権利があることを先に確認する必要があり、作ったファイルは自分だけで使います。ヒンティングは削除されます（影響は Windows の小さいサイズだけです）。和欧間の 1/8 em のアキはブラウザが自動で入れるもので、ほかのアプリでは入りません。

        
形式：結合は TrueType の曲線でしか行えないため、OTF は最後に結合結果を CFF の曲線に変換して作ります。ブラウザで動くフォントライブラリ（fontTools）は、和文 OTF で一般的な CID 形式の CFF を結合できず、TrueType と CFF の曲線を 1 つのフォントに混ぜることもできません。CFF を直接結合して CID 形式の OTF を作れる Adobe AFDKO は C のプログラムで、ブラウザでは動きません。そのため元のフォントが CFF の場合は「3 次曲線 → 2 次曲線 → 3 次曲線」と変換され（誤差は 1/1000 em 以内で、印刷では見分けられません）、できる OTF も CID 形式ではありません。今のアプリでは問題なく使えますが、CID フォントを求める古い印刷ワークフローでは受け付けられないことがあります。

        
font-size-adjust を使わない理由

        
font-size-adjust（2 値構文は Chrome 127、Firefox 92、Safari 17 が対応）でもサイズをそろえられますが、要素内のすべてのフォントに効きます。欧文を目標のキャップハイトに合わせると、漢字フォントも付属欧文のメトリクスに応じて拡大縮小されます。文字クラスごとにフォントを割り当てることもできないため、引用符の問題も解決しません。さらに MDN によれば、@font-face の size-adjust と併用すると size-adjust が効かなくなります。合成フォントを使う要素には font-size-adjust を指定しないでください。校正刷りの「他の方法と比較」で違いを確認できます。

Matching rules

        
One font-family can have several @font-face rules. For each character, the browser searches from the last rule backward and uses the first rule whose unicode-range includes it and whose font actually has the glyph. So the base font (Han) comes first, with no range, and covers everything else; classes such as Western and Digits come after it and take over their own ranges; exception characters come last and have the highest priority.

        
Size: size-adjust

        
size-adjust scales a font's glyphs and metrics by a percentage. It is supported in Chrome/Edge 92+, Firefox 92+ and Safari 17+. It also scales the font's ascent and descent, so with line-height: normal the line spacing can become uneven; set a fixed line-height.

        
In Base settings, size and baseline can be typed directly or adjusted by 0.5 using the arrows on the right of each input. The size inputs in Weights work the same way. Hold Shift while pressing ↑↓ on the keyboard to adjust by 5. Clear an input to restore its inherited value. Arrows appear on hover or focus and stay visible on touch screens; the numbers stay aligned as the arrows appear or disappear.

        
Baseline shift needs JS

        
@font-face has no baseline descriptor. All glyphs on a line sit on the alphabetic baseline, and CSS cannot move them per font. When you use the tool's baseline setting, the export includes a small script that wraps the affected characters in a <span> and moves them with relative positioning, without changing the line height. For pure CSS, keep every baseline at 0.

        
Auto-adjust

        
“Auto-adjust”, at the top right of Base settings, matches each independently chosen font by character class. The Han base font stays unchanged. Following classes inherit their source’s results; explicit size and baseline overrides are kept. When every target font matches its reference, a notice appears and settings stay unchanged. Fine-tune the results or undo the whole operation in one step. Notices slide in from the bottom, pause, then fade out; reduced motion disables the animation.

        
References. Western text uses the Han font’s built-in Latin letters, balancing capital and lowercase x heights; when those letters are missing, size is estimated from the Han character face. Independent digits use the Western digits fitted in this run. Kana, full-width punctuation, symbols, Zhuyin and independent shared punctuation use the corresponding characters in the Han font. Kana, digits and Zhuyin match character heights. Full-width punctuation, symbols and shared punctuation match character advances for size, then corresponding glyph positions, preserving small punctuation faces and regional placement rather than enlarging every glyph to Han height.

        
Exception characters. Independent groups of up to 64 characters from one original class use that class’s current font as their reference. Mixed classes, unclassified characters, larger ranges and missing reliable references keep their settings and are reported. If any measured weight lacks a reference, that entire class is kept, so changing its base cannot indirectly alter an unmeasured weight.

        
Weight and baseline. Stepped mode compares strokes at the fitted size and chooses closer available weights without making bold lighter than body text in the same font. Western text uses the main strokes of H and h; other classes estimate stroke width from horizontal and vertical slices through corresponding characters. These measurements are a starting point for visual matching. Google Fonts and local or uploaded fonts with a weight axis are supported. Continuous mode, single-weight fonts and unreliable stroke measurements keep weights unchanged. Selected export weights and always 400 are measured. The 400 result goes into Base settings; other sizes are stored separately when they differ by at least 0.5 percentage points. Only the base baseline is stored; shifts below 2% em become 0. Web shifts need JS; font files store the positions directly.

        
Reset and limits. The reset button beside each class heading in Weights restores its base size to 100%, baseline to 0 and adjustable weight to the available value nearest regular 400, then clears its per-weight size, weight and font overrides. It keeps the base font choice, other variation axes and classes, shared font-name mappings, export selections and preview weight, and can be undone. Auto-adjust cannot create missing weights and does not change export selections. Check shapes, serif contrast and design proportions in body text, then fine-tune or change fonts as needed.

        
Installed fonts: local()

        
local() matches a font’s full name or PostScript name, not its family name. For example, write Hiragino Sans GB W3 or HiraginoSansGB-W3, not Hiragino Sans GB. A green dot on a font card means the current browser found the font. Safari lets web pages use only the fonts that come with the system; fonts you installed yourself don’t work in Safari. If a visitor’s computer doesn’t have the font, the browser falls back to the previous rule.

        
Google Fonts

        
On Google Fonts, CJK fonts are split into a hundred or more slices, each with its own unicode-range. On export, the tool intersects each slice’s range with the class’s range and keeps only the slices it needs, so the Western class usually ends up with one or two rules. The URLs point to fonts.gstatic.com; for production, download the files and host them yourself.

        
Exporting several weights

        
Font names show “Continuous weights” or “Stepped weights”. Continuous weights accept any value in their range, for example “Continuous weights 200–900”. Stepped weights offer fixed values, for example “Stepped weights 400, 700”; longer lists show their lightest-to-heaviest range, with the full list on hover. These labels describe the font’s capabilities; choose the export mode separately in Weights. Ranges are never guessed. Fonts with variable axes but no readable weight range show “Weight range unknown”. Fonts that follow another class use the information in that class’s row.

        
Check the weights to export in Weights (you can also choose them in the export dialog); each weight gets its own set of rules. Click empty space in any row to preview that weight without changing the export selection. The fonts you set in the tool correspond to 400. For other weights, Google Fonts fonts are shifted by the same difference (a font set at 500 becomes 800 at 700), or the nearest available weight if that one doesn’t exist; for installed fonts, the tool guesses the bold name (W3 → W6, Regular → Bold, and so on) and checks for it on this computer. Fonts don’t distribute their weights the same way: in the Weights table you can adjust each class’s size and weight separately for each weight. For variable fonts, type any weight or use the arrows on the right or keyboard ↑↓ to adjust it by 10 (Shift + ↑↓ for 100). Static Google Fonts step by 100, skipping unavailable weights. To set an installed font name, a font file, or a different font for just that weight, click that cell, or use “change font…” in the “⋯” menu at the end of the row, and choose it in “Choose font”. For static Google Fonts fonts, only the weights the font actually has are listed; grey values are computed, blue ones are set for that row, and picking the grey value again clears the row’s setting.

        
The rules for different weights can’t be combined. CSS variables (var()) don’t work inside @font-face; the browser simply drops the descriptor. If some rules in one font-family say font-weight: 700 and others say 400 700, Chrome (in testing) splits them into two groups and uses only one, and the composite font stops working.

        
Most of the size comes from the hundreds of slices of the Han font on Google Fonts. “Base font: Link Google Fonts (shortest)” references Google’s CSS directly with @import, puts that font second in font-family, and writes only the classes that override it, so the exported CSS is usually just a few KB. Servers usually compress CSS with gzip, so the gzip size shown in the export panel is closer to what is actually transferred. Font files are downloaded only for the characters a page uses, regardless of the length of the CSS.

        
In stepped mode, applying changes in the font picker or changing which class a row follows checks the actual font and weight used in each row. Selected export weights clearly outside a known range are unchecked, with Web and font-file selections checked separately. Valid individual mappings, gaps within a static font’s range, and fonts with unknown ranges are kept. Unchecking a row preserves its adjustments, and you can select it again. The font change and automatic unchecking can be undone together. If every selected weight in a group is out of range, the selection is kept with a notice to review it. Switching to a font with a wider range does not select more weights. Continuous-mode selections and ranges are not adjusted.

        
Italics

        
Without italic rules, the browser synthesizes slanted text for everything inside <em> and <i>: Western text doesn’t use its real italic even when one exists, and Han characters get slanted too. So italics are exported by default, and each set of rules gets an extra copy with font-style: italic: Western text uses a real italic (the Italic from Google Fonts, an uploaded italic file, an installed “… Italic”, or the slnt / ital axis of a variable font); classes without an italic use their upright file, also declared as italic, so the browser doesn’t synthesize one. When the base font is referenced with @import, Google only provides the upright style, so the usage rule adds font-synthesis-style: none to keep it upright as well.

        
Variable axes

        
In “Choose font…” you can adjust a variable font’s other axes, such as width, grade (GRAD) and optical size. Google Fonts keeps only the axes named in the request, pins the rest at their defaults and removes them from the file, so any axis you adjust is added to the request and the file roughly doubles in size. Pinned values are written to font-variation-settings in @font-face; Safari ignores that line and shows the defaults. When optical size is set to “Follow font size”, the browser sets opsz from the actual font size; in testing, Chrome uses the size after size-adjust scaling, which matches the size at which the Western text is actually shown.

        
“Figure style” and “Slashed zero” under “Font features” in the Fonts tab map to font-variant-numeric and are written into the usage rule (Chrome 52+, Firefox 34+, Safari 9.1+); on the page you can also change them per element, for example to use tabular figures only in tables. Whether they work depends on whether the font that displays the digits has these OpenType features: the tool detects which kind of figures the font uses by default and warns you when you pick a style it lacks. The Google Fonts web fonts have most features removed and have no old-style figures or slashed zero.

        
Line metrics: the browser takes the composite font’s line height (line-height: normal) and the position of the baseline within the line from the rule that covers the space character, that is, the Western font, and after size-adjust scaling. By default, the export writes the Han font’s ascent-override, descent-override and line-gap-override into every rule other than the base font; size-adjust scales them again, so the values written are already divided by it. Text then sets the same as with the Han font alone. Supported in Chrome 87+ and Firefox 89+; Safari ignores them.

        
Traditional Chinese: Taiwan and Hong Kong

        
Traditional Chinese in “Target language” comes in two versions, Taiwan and Hong Kong. The export uses :is(:lang(…)) to cover the common ways of writing the language tag: the Taiwan version matches zh-Hant and zh-TW, the Hong Kong version matches zh-HK, zh-Hant-HK and the Macau tags. The reason is that :lang(zh-Hant) doesn’t match lang="zh-TW": browsers don’t infer the script from the region. Simplified Chinese likewise adds zh-CN and zh-SG.

        
Both regions differ from mainland China: punctuation sits in the center of the character body (in mainland China and Japan it sits at the lower left), and glyph shapes follow each region’s own standard. The tool measures the position of full-width punctuation and judges a font’s glyph region from its family name: if it doesn’t match the proof language, the class table shows a warning; if it doesn’t match the target language, the export panel does. Fonts such as Source Han and Noto CJK, which contain glyphs for several regions in one file, switch by lang, so measurements are taken with the language set as well.

        
The class table has a “Zhuyin” row that also covers the tone marks ˊ ˇ ˋ ˙: they sit at Latin-script code points, and unless they are moved over they are shown in the Western font. Accented letters in French and other languages (é, à) are separate code points and are not affected; if needed, you can move the tone marks back to Western under the gear icon.

        
App code (experimental)

        
iOS, Android and Flutter have no composite fonts. “App code” in the export generates Swift, Kotlin or Dart code that splits text into runs by character class and gives each run its own font, size and baseline shift; the character ranges are exactly the same as in the web export. The font names in the code (PostScript names, file names, family) are guesses; change them to match the fonts actually bundled with your app. Mixing text of different sizes changes the line height, and there is no line-height correction as on the web; Flutter can’t shift the baseline of individual runs. All three kinds of code have been compiled (Kotlin against the Android API, Flutter through analyze and test) and the splitting has been checked, but the typesetting has not been looked at on real devices. If you find a problem, please open a PR or issue on GitHub. If the font licenses allow it, bundling the generated font files with your app gives the most complete result.

        
Font files

        
The Font files tab turns the composite font into a real font (TTF, WOFF2, OTF, in any combination) for apps such as Figma, Keynote and Word that don’t support composite fonts. It follows the exported CSS one to one: from each rule’s font it takes only the characters that rule covers, scales them by the size, shifts them up or down by the baseline, and merges everything into one font; line metrics come from the Han base font. Generation runs in the browser (Pyodide + fontTools), and fonts are never uploaded to any server.

        
Source fonts: Google Fonts fonts are downloaded as complete files from the google/fonts repository, because the slices served by the web API have most OpenType features removed; uploaded fonts are used as is; installed fonts are read through the browser’s Local Font Access API (Chrome, Edge; requires permission). OTF fonts with CFF outlines are converted to TrueType curves (error no more than 1/1000 em), and from a font collection (TTC) only the face in use is taken. Only fonts under licenses that allow modification, such as OFL and Apache, can be merged without further checks; for fonts with an unclear license (including fonts that come with the system and commercial fonts), first make sure you have the right to modify them, and keep the generated files for your own use. Hinting is removed, which only affects small sizes on Windows. Browsers automatically add 1/8 em of space between CJK and Western text; other apps don’t.

        
Formats: merging works only on TrueType curves, so OTF is produced at the end by converting the merged result to CFF curves. The font library that runs in the browser (fontTools) can’t merge CID-keyed CFF, which Chinese and Japanese OTF fonts commonly use, and can’t put TrueType and CFF curves in the same font; Adobe AFDKO, which can merge CFF directly and produce CID-keyed OTF, is a C program and can’t run in the browser. So when a source font is CFF, it goes through a cubic → quadratic → cubic curve conversion (error no more than 1/1000 em, invisible in print), and the resulting OTF is not CID-keyed. Current apps handle it fine; a few older print workflows that require CID fonts may not accept it.

        
Why not font-size-adjust

        
font-size-adjust (two-value syntax supported in Chrome 127, Firefox 92 and Safari 17) can also even out sizes, but it applies to every font in the element: while it brings the Western text to the target cap height, the Han font is also scaled according to the metrics of its own built-in Latin letters. It also can’t assign fonts by character class, so it doesn’t solve which font the quotation marks belong to. More importantly, MDN notes that when it is used together with size-adjust in @font-face, size-adjust no longer has any effect. So don’t set font-size-adjust on elements that use a composite font. You can switch the proof to this approach under “Compare with other methods” to see the difference.
